## What this is

A single-page Three.js "terrarium" that procedurally generates a small floating-island world (biome, terrain, flora, creatures, birds, particles) from a 16-bit seed. Vite provides the dev server (HMR) and optimized production builds. Three.js and simplex-noise are npm packages, bundled and tree-shaken. Live site: https://small-world.pardev.net/

## Navigation quick start

Start with `README.md` for the user-facing product shape, then `index.html` for the static HUD markup (no importmap or CDN dependencies — everything is bundled by Vite), `main.js` for renderer/camera/animation-loop wiring, and `src/world.js` for the deterministic world-generation orchestration. Use `src/state.js` to understand shared mutable state before changing cross-cutting behavior. Feature work usually lands in one concern module under `src/` plus, when visible in the HUD/settings, the relevant `src/ui/` sub-module (`src/ui.js` is a thin entry point that just wires them up — see its Architecture bullet), `index.html`, and `style.css`. Portal work starts in `src/portal.js` (called from `src/world.js`); biome music in `src/music.js` (wired from `src/ui/settings-panel.js`); post-processing in `src/postfx.js`.

- `ideas.md` — curated enhancement backlog; completed items should be removed.

## Running it

`make dev` starts the Vite dev server in the foreground with hot reload on `http://localhost:2001`; `make dev-start` / `make dev-stop` / `make dev-restart` manage the same Vite server in the background. Edits to `main.js` / `src/*.js` / `style.css` / `index.html` are reflected instantly without a full reload when possible.

`make build` produces an optimized production bundle in `dist/` (minified, tree-shaken, content-hashed assets). `make preview` serves the built output locally.

```
make dev          # Vite dev server with HMR in the foreground
make dev-start    # Vite dev server with HMR in the background
make dev-stop     # stop the background dev server, or any process on PORT
make dev-restart  # restart the background dev server
make build        # production build → dist/
make preview      # preview production build
make lint         # ESLint over main.js and src/
make test         # all JS tests
make checkall     # all JS tests + lint + production build
make clean        # rm -rf dist
```

Runtime dependencies (three.js, simplex-noise) are installed via npm and bundled by Vite — they're no longer loaded from CDN. `node_modules/` is gitignored; run `npm install` before `make dev` or `make build`.

## Testing

`make test` runs the full suite: every `tests/*.test.mjs` file via plain `node` (no test runner/framework — each file asserts with `node:assert/strict` and exits non-zero on failure). `make checkall` runs `make test` followed by `make lint` and `make build`.

To run a single test:

```sh
node tests/determinism-seed.test.mjs
```

Most `*-static.test.mjs` files are **static invariant tests** — they import a module (e.g. `BIOMES` from `src/biomes.js`) or read source text and assert on its shape (a biome has a given flag, a constant has a given value, a code path exists). They catch config drift and accidental removal of a documented mechanism, but a pure refactor that preserves behavior can still break one — update the assertion to match the new shape rather than treating the failure as a regression. A smaller set of tests (no `-static` suffix, e.g. `caterpillar-trail-trim.test.mjs`, `fish-speed.test.mjs`, `portal-preview-pool-isolation-runtime.test.mjs`) exercise actual runtime behavior and should be treated as real regressions if they fail.

`tests/determinism-seed.test.mjs` is the guardrail for any change to world-gen: it verifies that the same seed reproduces the same world across regenerations. Anything that touches the seeded-PRNG window (see "The determinism trick" below) must be checked against this test — a subtle ordering change (a stray `Math.random()`, a re-ordered builder call) shifts the RNG stream for every seed without necessarily throwing an error.

## Version

The app version is defined in `package.json` (`"version"` field). It's injected into the app at build time via Vite's `define` config and appears in the header eyebrow as "vol. X.Y.Z".

**Always bump `version` in `package.json` before pushing.** Use semantic versioning (major.minor.patch):
- **patch** — bug fixes, small tweaks
- **minor** — new features, new biomes, new creatures
- **major** — breaking changes, major reworks

CI reads `package.json` and passes the version to the build, so the deployed site always shows the correct version.

## Release/deploy

Pushing to `main` triggers the GitHub Actions workflow (`.github/workflows/deploy.yml`) which runs `npm ci && npm run build` and deploys the `dist/` output to GitHub Pages. The `CNAME` file (`small-world.pardev.net`) is copied into the build output for the custom domain. `dist/` is gitignored — only source files are tracked; the bundle is built fresh by CI on every push.

Biome music is not shipped through GitHub Pages. `src/music.js` streams tracks from `https://static.pardev.net/small-world/music/`, backed by `/docker/static/data/small-world/music/` on `lenny1`. Keep `public/music/` gitignored; it is only a local staging/convenience folder for MP3s before copying them to the static host.

Before pushing, always:
1. Bump `version` in `package.json`
2. Add a matching `CHANGELOG.md` entry (Added/Changed/Fixed/Verified sections, newest at top)
3. Commit the version bump alongside (or just before) the changes
4. Push to `main`

**Commit messages** use Conventional Commits — `type(scope): summary` (e.g. `feat(postfx): mip-chain bloom`, `fix(ui): mobile fly controls`, `chore(release): 1.4.0`). The release commit that bumps `package.json` is `chore(release): X.Y.Z`.

## Architecture

The app is one Vite-bundled ES module graph. Entry point `main.js` wires the renderer, camera, OrbitControls, kicks off `generateWorld(seed)`, and runs the `animate()` loop. `index.html` provides only the static HUD markup and CSP meta tag — no importmap, no CDN script tags. Everything else lives in `src/`:

- **`src/state.js`** — the shared module-scope singleton. `state` holds `world` (the THREE.Group that's disposed/rebuilt every regen), all entity arrays (`creatures`, `caterpillars`, `butterflies`, `bees`, `flocks`, `dirtPuffs`, `dustKicks`, `flowerSpots`), `heightFn`, `currentBiome`, `currentLayout`, `ISLAND_SIZE`/`ISLAND_RADIUS`, `windUniforms`, `userSettings`, plus refs for the visual-polish modules: `shadowDisks`, `waterReflection`, `mountainBasePos`, `postfx`, `renderer`, and `depthTexture` (set by `initPostFX` for depth-based post-processing). Also `obstacles` (entries `{x, z, r, top}` — `top` is the canopy world-Y consumed by the air-passing height filter in `avoidObstacles`) and `perchSpots` (entries `{x, z, y}` — mushroom-cap landing pads consumed by the flier landing code). Every other module imports from here rather than passing things around. Also exports `disposeGroup` (accepts an optional `{ skip }` Set of geometries/materials to leave undisposed — used on individual-rejection placement paths so a pooled resource isn't disposed out from under other consumers), the night-palette constants, and the `ISLAND_SIZE_BASE` / `DENSITY_BASE` anchors (see "Density scaling" below). `userSettings` covers atmosphere knobs, five FX controls (`bloom`, `tiltShift`, `outline`, `ao`, `depthFog`) with `fxPanelOpen`, three wind controls (`windEnabled`, `windStrength`, `windNoiseScale`) with `windPanelOpen`, and three grass controls (`grassEnabled`, `grassDensity`, `grassHeight`) with `grassPanelOpen` — all persisted to localStorage by `src/ui/storage.js`. `grassDensity` and `grassHeight` are internal multipliers (× biome stock, × blade geometry height); the settings sliders rebase the display against the canonical `GRASS_DENSITY_BASE = 25` / `GRASS_HEIGHT_BASE = 0.96` constants **exported from this file** (imported by `ui.js` and `src/ui/storage.js` — distinct from the world-gen `DENSITY_BASE` anchor also in `state.js`), so 100% on the slider corresponds to those internal units.
- **`src/seed.js`** — `mulberry32`, `parseSeed`/`formatSeed`, `readSeedFromUrl`/`writeSeedToUrl`, `newRandomSeed({excludeBiomeId, allowedBiomeIds})`. Seeds are 16-bit hex (e.g. `0x3f2a`).
- **`src/biomes.js`** — the `BIOMES` config table (currently twelve entries) plus `WILDFLOWER_PALETTES` / `GRASS_DENSITY` / `FLOWER_DENSITY` / `PEBBLE_DENSITY` overrides and `EDGE_AURA_DEFAULTS` (a shared base config spread into each biome's `edgeAura` override, replacing what used to be ~100 lines of duplicated per-biome config). Each biome fully specifies palette, fog, accent/sun colors, allowed flora kinds + count, particle type, creature color palette + count range, plus optional dusk/night palette deltas. Optional flags (`water`, `cloudlike`, `glowFlowers`, `glowEyes`, `furProbability`, `creatureKind`, `hasWillowisps`, `giantFlora`, `guaranteeBurrower`, `treeFloraRadiusFrac`) gate cross-cutting behavior — see "Biome-flag pattern" below. Adding visual variety usually means editing this table, not the builders.
- **`src/terrain.js`** — `makeHeightFn(noise2D, layout, amp)` returns a `(x,z) => y` closure combining three simplex-noise octaves with a per-center smoothstep falloff (`islandFalloff`) so each island has a defined edge that plunges into void past its radius. `makeTerrain` bakes that into a vertex-colored `PlaneGeometry`. `pickLayout()` and `pickGroundPoint(maxRadiusFrac)` / `nearestCenter(x,z)` live here.
- **`src/flora.js`** — a thin public registry, not a builder file. It re-exports `FLORA_BUILDERS` (a `{ kind: (biome) => THREE.Group }` map keyed by flora kind string), `resetFloraPool`, `withIsolatedFloraPool`, and `jitterGeo` (defined in `src/util.js`). The builders themselves live under `src/flora/`, split by family (mirroring the `src/fauna/` split): `_shared.js` (the per-regen resource pool + shared placement helpers), `trees.js` (tree/leafballtree/pine/snowpine), `garden.js` (dandylion/cactus/mushroom/fern/reed/seaweed/grass/beachsucculent/berrybush), `rocks.js` (rock/limestonerock/skull/pillar/archstone), `structures.js` (flyer_nest/deadtree/crystal/bigmushroom/fairyring/lantern), `aquatic.js` (coral/braincoral/cupcoral), and `volcanic.js` (balloontree/lavafissure/obsidianglass/obsidianshard). Biomes still reference builders by string key from their `flora` array. `resetFloraPool()` must run at the top of every regen since the previous world's materials/geometries were just disposed. `withIsolatedFloraPool(fn)` runs `fn` against a scratch pool instance instead of the shared one — this is what lets portal previews (`src/portal.js`) render a different biome's flora without leaking that biome's cached materials into the live world's shared pool (see the `pool.js` entry below).
- **`src/fauna.js`** — barrel re-export of the per-entity modules under `src/fauna/`: `creature.js`, `caterpillar.js`, `butterfly.js`, `bee.js`, `willowisp.js` (`state.willowisps`, stepped in its own `animate()` phase), plus `shared.js` for cross-entity helpers (`WATER_AVOID_Y`, `avoidObstacles`, `colorsClose`; imported directly by sibling modules, not re-exported through the barrel). Each module exports its `makeX` / `stepX` pair and returns `{ group, …state }` with no base class; the animation loop iterates parallel arrays on `state`. Consumers always import from `./fauna.js`, never the per-entity files. `creature.js` itself is split by concern: `creature-mound.js` owns the burrower dirt-mound visuals and the `stepBurrower` FSM; `creature-perch.js` owns perch bookkeeping (`currentPerchPoint`, `claimPerchForFlier`/`releasePerchForFlier`, `pickPerchForFlier`) and the flier landing FSM (`stepFlier`); `creature-sleep.js` owns sleepiness easing, the rising-"z" sleep particles, and the `stepSleeper`/`stepNightSleep` poses. `creature.js` retains `makeCreature` and the `stepCreature` dispatcher, which hands off early to `stepSleeper`, `stepNightSleep`, `stepBurrower`, or `stepFlier` before falling through to three per-frame helpers for plain walkers/fliers: `stepThink` (random heading jitter, herding, curiosity hops, perch-homing steer, family-kid follow), `moveCreature` (edge avoidance, obstacle sliding, water guards, speed integration), `positionCreatureY` (ground/water/perch floor height blend), and `animateCreature` (facing, terrain-slope tilt, squash & stretch, wing/leg/foot animation and footstep marks) — each a module-private function called in that fixed order every frame.
- **`src/birds.js`** — `makeFlock(biome)` + `stepFlock(flock, dt, t)`. Unlike every other entity module, the object `makeFlock` returns has no `.group` — the flock is a loose collection of individually-grouped birds rather than one parented `THREE.Group`, so `stepFlock` and any disposal code must walk the flock's own bird list rather than expecting a single top-level group.
- **`src/grass.js`** — `makeGrassField` (instanced grass-blade rendering with per-biome density / baldness). Re-exported from `environment.js` for backward compatibility, so callers can keep importing it from there. The field pre-allocates `MAX_DENSITY_MULTIPLIER × biome stock` slots so the user's density slider can raise `mesh.count` past 100% without a regen; `state.grass = { mesh, uniforms, stockCount, maxPlaced }` exposes the bounds the UI clamps to. The shader has three runtime control points beyond the existing wind sway: `uHeightMul` (multiplies `transformed.y` for the height slider), `uPushers[MAX_PUSHERS]` + `uPusherCount` (creature → grass bend, see "Grass push system" below), and `uWindStrength` / `uWindScale` (live multipliers driven by the wind panel; freezing wind also stops `state.windUniforms.uTime` from advancing in `main.js`).
- **`src/environment.js`** — barrel re-export of the per-concern modules under `src/environment/`, mirroring the `src/fauna.js` split: `particles.js` (per-biome particle systems — a single `ShaderMaterial` with per-kind `#define PARTICLE_KIND` and per-particle `aSeed`/`aLife` attributes so ember/spark fade with life, rain reads as streaks, firefly twinkles per-particle), `swarms.js` (dirt puffs, footstep dust kicks, and the desert skull fly swarm — `makeDirtPuff`/`stepDirtPuffs`, `makeDustKick`/`stepDustKicks`, `makeFlySwarm`/`stepFlySwarms`), `decals.js` (the terrain-shader-painted soft-ground creature marks — `makeGroundMarks`/`emitGroundMark`/`stepGroundMarks`), `groundcover.js` (the shared `placeInstanced` rejection-sampling placer plus `makeWildflowerField`/`makeVerdantGroveDetails`/`makeCloudPuffField`/`makePebbleField`/`makeBeachcombField`), and `water.js` (`makeWaterPlane`/`stepWater`; the water material's `onBeforeCompile` is patched to sample `state.waterReflection.rt` and Fresnel-mix it into the surface color). `_shared.js` holds the `lowfxScale`/`coverScale` density helpers consumed by `particles.js`, `swarms.js`, and `groundcover.js`. Consumers always import from `./environment.js`, never the per-concern files. The barrel also re-exports `makeGrassField` from `src/grass.js`. Wildflowers return positions for butterflies to target via `state.flowerSpots`.
- **`src/sky.js`** — backdrop primitives: gradient sky dome, two-layer wobbled mountain ring, drifting cloud sprites, twinkling starfield, aurora curtains for cold/dreamy biomes, and `makeCloudSwirl` — a torus halo of shader-swirled clouds for the cloudlike biome. `updateSkyColors` re-tints the dome and mountains from the day/night palette; star/aurora opacity is driven by the night factor each frame. Per-biome cloud counts and aurora opt-ins live in the `CLOUD_COUNT` / `AURORA_BIOMES` / `AURORA_TINTS` tables in `biomes.js`.
- **`src/shaders/noise.js`** — shared GLSL chunk strings for the hand-rolled hash/value-noise helpers previously copy-pasted inline across `sky.js` (×3), `grass.js`, and `flora/volcanic.js`. Each shader interpolates the `GLSL_*` chunk(s) it needs into its own template literal. Several near-identical variants exist deliberately (different hash magic-constant precision, prefixed function names to avoid colliding with three.js's generated shader chunks) rather than one unified version, since merging them would change the actual noise values a given shader produces.
- **`src/world.js`** — `generateWorld(seed)`, the orchestrator (QA-008 split its ~1,360-line body into the `src/world/` phase modules below). Disposes the previous `state.world`, picks biome + layout deterministically (via `rollBiomeAndLayout` in `src/world-constants.js`, shared with the portal preview), then awaits each phase in order — `buildAtmosphereAndTerrain` → `placeFloraAndGroundCover` → `populateFauna` → inline bird flocks/particles/shadow disks — before handing off to `finalizeWorldHud` (`src/world-hud.js`) for HUD/URL/spatial-index bookkeeping. Every phase function is awaited at the exact point its body used to sit, so the seeded-PRNG-window mechanics (see "The determinism trick" below) are unchanged by the split; phase functions that themselves call `yieldIfNeeded` receive it as a parameter rather than reimplementing it. Also exports `updateDayNight(t)` (the day/night color/sun lerp called from `animate`) and the `setSceneRef` / `setControlsRef` / `setFollowReleaseCallback` wiring used by `main.js`. `CANOPY_SPACING_KINDS` / `CANOPY_SPACING_PAD` are re-exported here for back-compat but now canonically live in `world-constants.js` (so `src/world/flora-placement.js` can import them without a cycle back through `world.js`).
- **`src/world-constants.js`** — constants and helpers shared between `world.js` and the portal preview (`portal.js`) so the preview can never silently diverge from the real destination world: `terrainNoiseFromSeed(seed)` (canonical terrain-noise permutation), `rollBiomeAndLayout(pickLayoutFn)` (the exact one-`Math.random()`-then-`pickLayout()` RNG prefix — see "Seed → biome → layout coupling" below), `terrainAmpFor(biome)`, `WATER_SURFACE_Y` (the water-plane surface height, also read by `main.js` and `environment.js`), `applyWaterWetDepth` (softens terrain below the waterline into a smooth trough), `applyFlatZonesToHeightFn` (patches a heightFn for flattened zones like portal pads and fairy rings), `sampleFootprintHeights` (9-point radial height sampler for slope-planting flora), the `FLORA_FOOTPRINT` per-kind radius table, and `CANOPY_SPACING_KINDS` / `CANOPY_SPACING_PAD` (the broad-canopy placement-spacing Set/pad, also consumed by `src/world/flora-placement.js`).
- **`src/world/atmosphere.js`** — `buildAtmosphereAndTerrain(ctx)`, the first `generateWorld` phase (QA-008): biome-switch music, postfx bloom/depth-fog tint, scene background/fog, hemi/sun/accent lights, sky backdrop (dome/mountains/clouds/starfield/aurora/cloud-swirl/edge-mist), the day/night palette snapshot (`worldState.dayNight`), then terrain (`makeHeightFn`/`makeTerrain`) and the optional water plane + reflection RT. Contains the two `yieldIfNeeded(true)` calls that used to sit at this point in `generateWorld`.
- **`src/world/flora-placement.js`** — `placeFloraAndGroundCover(ctx)`, the largest extracted phase: delegates portal placement to `placePortals` (`src/world/portal-placement.js`), places the fairy-ring landmark, prewarms PBR detail textures, runs the main flora placement loop (canopy spacing via `CANOPY_SPACING_KINDS`/`CANOPY_SPACING_PAD`, giant-flora promotion, obstacle/perch registration), tops up reef corals, then delegates ground cover to `placeGroundCover` (`src/world/ground-cover.js`). Returns `{ placed, blocksPlacement, GROUND_CREATURE_BLOCK_KINDS, placeFlyerNest }` — `placed` feeds the HUD flora count, and the other three are reused by `populateFauna` (ground-creature collision checks and the post-creature flyer-nest top-up both need helpers built during flora placement, since flyer-nest count depends on how many fliers the fauna phase actually placed).
- **`src/world/portal-placement.js`** — `placePortals(ctx)`, called from `flora-placement.js`. Picks 1–2 neighboring target biomes (`getPortalTargetBiomes`/`findNextPortalBiome`), seeds each portal's placement (`makeSeededPortalPlacement`), and builds it (`createBiomePortal`); pushes blockers/obstacles into the caller's shared `floraPlacementBlocks` array and flattens terrain via the caller's `flattenTerrainCircle`. Purely synchronous — no `yieldIfNeeded` calls, so it doesn't touch the seeded-PRNG-window mechanics.
- **`src/world/ground-cover.js`** — `placeGroundCover(ctx)`, called from `flora-placement.js` after the main flora loop. Builds instanced grass/wildflowers/grove details/cloud puffs/beachcomb/pebbles/ground marks, excluding fairy-ring and portal clearings via the caller's `floraPlacementBlocks`.
- **`src/world/fauna-population.js`** — `populateFauna(ctx)`, the phase after flora placement: ground creatures (family/sleeper/burrower/plain budget rolls, fish placed underwater in water biomes, angler fish), the flyer-nest top-up (via the `placeFlyerNest` helper handed back from flora placement), caterpillars/snails, butterflies, and bee swarms.
- **`src/world-hud.js`** — `finalizeWorldHud(...)`, the HUD/URL/spatial-index tail of `generateWorld`. Runs after every deterministic placement and after the final `yieldIfNeeded(true)`, so it makes no `Math.random()` calls and sits entirely outside the seeded PRNG window. Writes biome/creature/flora/bird/seed stats to the HUD and the mobile help panel, dispatches the `"world-ready"` `CustomEvent` that `ui.js` listens for, restores the user's auto-rotate preference, writes the seed back to the URL, builds the obstacle spatial grid (`buildObstacleGrid`) and per-color creature herding buckets, and arms the reveal-animation timestamp.
- **`src/ui.js`** — the thin public entry point for all HUD DOM wiring (ARC-001 / QA-006 god-module split). `initUi({camera, canvas, controls, renderer})` seeds the shared `src/ui/context.js` singleton with the renderer refs, then calls each sub-module's `initX()` in an order that preserves the original event-listener registration sequence (settings before input so the wind/grass `"world-ready"` rebase registers before the mobile-header fade; the panels that own `setSettingsOpen`/`setLocatorOpen`/`setCatalogOpen` before `help-panel` whose first-visit block calls them; `first-person` before `input` so its canvas pointer listeners precede click-to-pick). `ui.js` itself only defines the pure-`ctx` predicates `isSelectingCreature()` / `isManualPaused()` and re-exports the full public surface (`initUi`, `loadSettings`, `getFollowTarget`, `setFollowTarget`, `stepStroll`, `stepTour`, `isStrolling`/`isFlyMode`/`isPhotoFP`/`isAnyFP`, `isPhotoMode`, `isTouring`, `enterStrollFromPortal`, `setStrollLocalPose`, `getPhotoReviewGroup`) from the sub-modules so `main.js`'s imports are unchanged. The concerns split under `src/ui/`:
  - **`context.js`** — the shared mutable `ctx` object. Mirrors the former module-scope `let`s (mode/selection state: `followTarget`, `selectingCreature`, `stroll`, `flyFP`, `photoFP`, `photoReview`, `manualPause`, `tour`, catalog/locator open flags) plus the renderer refs and the cross-module functions each sub-module attaches (`ctx.setSettingsOpen`, `ctx.setPhotoMode`, `ctx.stopTour`, …) so siblings can call each other as `ctx.fn()` without importing in a cycle. No-op defaults keep an early call harmless.
  - **`settings-panel.js`** — the settings panel: atmosphere (scale, auto-rotate, day/night, fog, ambient), reset-camera, wind, grass, ground-mark lifetime, portal preview, post-FX, music, FPS, auto-regenerate, share/copy-link. Owns `applyWindSettings`/`applyGrassSettings` and the ARC-005 `"world-ready"` listener that re-baselines the wind/grass shader uniforms after every regen (via the `state._reapplyWindSettings`/`state._reapplyGrassSettings` hooks it installs) — the sole reapply mechanism; there is no redundant poll.
  - **`help-panel.js`** — help panel + first-visit help, biome filter chips (exposes `ctx.pickRandomBiomeSeed`/`ctx.pickSameBiomeSeed` for regen), and bookmarks (`ctx.syncBookmarkButton`).
  - **`catalog-panel.js`** — the Field Guide catalog panel and its `makeCatalogStore()` (module-scope, IndexedDB + localStorage). Exposes `ctx.catalogStore` / `ctx.renderCatalogPanel` for photo mode's save flow (see "Field Guide catalog" below).
  - **`locator-panel.js`** — locator panel + follow mode + cinematic tour. `setFollowTarget` / `stepTour` / `isTouring` / `getFollowTarget` are module-scope (main.js imports them / steps the tour per frame) and read `ctx`; `generateWorld` calls `setFollowTarget(null)` on regen via the release callback registered here so a stale ref doesn't survive `disposeGroup`.
  - **`first-person.js`** — the shared `makeFirstPersonMode({ canvas, getFp, extraKeys, ignoreLockLossIf })` factory (QA-007, pointer-lock state machine + mouse-look + key mapping) used by stroll, fly, and photo mode; the `stepStroll` per-frame integrator; and the stroll (F/WASD, eye height `groundY + 1.9`) + fly-camera (V/WASD + E-Q, unclamped) enter/exit wiring including the mobile fly touch controls. `main.js` wakes any sleeper within ~2.5 units of the player while strolling.
  - **`photo-mode.js`** — photo mode (P key, click/space capture, save-to-png, freeze the sim), the 3D photo review, and the reticle catalog capture (uses `findPhotoCatalogSubject`; reaches into `ctx.catalogStore`/`ctx.renderCatalogPanel`). Exports `isPhotoMode()` / `getPhotoReviewGroup()`.
  - **`input.js`** — the cross-cutting global glue (initialises last): manual pause, the regen buttons + `R/r`, the 250ms seed-change watcher (bookmark label, photo HUD seed, biome overrides, music track select, locator reset — **not** wind/grass, which is event-driven), canvas click-to-pick (raycaster pick from `state.creatures` + `state.caterpillars`; **empty-space clicks during selection mode are ignored** so the user can drag the camera without cancelling), portal-entry / shift-click-inspect, hover-to-wake, resize, popstate, the mobile header fade, and the master keyboard handler (T tour, L locator, G catalog, spacebar manual pause, `,` settings) that routes to every panel/mode via `ctx`.
  - **`constants.js`** / **`storage.js`** — pre-existing DOM-free constants/helpers and the localStorage persistence layer (ARC-003 / QA-004).

- **`src/postfx.js`** — `initPostFX(renderer, scene, camera)` builds an `EffectComposer` chain (InputPass copying the depth pre-pass color → combined depth-FX pass → bloom composite → tilt-shift pass → custom sRGB-only output) and a **separate depth pre-pass RT** outside the composer's ping-pong. The pre-pass renders the scene into `depthRT` (with an attached `DepthTexture`) before `composer.render()`, only when some depth-using FX is enabled. Keeping the depth attachment off the composer's own ping-pong RTs avoids a WebGL feedback loop (sampling a depth texture while writing to the FBO that owns it gives undefined/all-black output). The `depthTexture` is exposed on `state` for depth-based post-processing passes.
  - Bloom is layer-gated, not luminance-gated. Meshes that should glow call `mesh.layers.enable(BLOOM_LAYER)` at construction (glow eyes, glow flowers, crystal cores, lantern orbs, obsidian shards). Bloom is a **mip-chain pipeline** (Jimenez, SIGGRAPH 2014), run hand-rolled in `renderBloomChain` outside any composer: the capture saves the camera's layer mask, sets `cam.layers.set(BLOOM_LAYER)` and `renderer.autoClearDepth = false`, and renders emissives into a **full-resolution HalfFloat** `bloomRT` that **shares its depth attachment with the depth pre-pass's `depthTexture`** — emissives behind opaque geometry get culled naturally by depthTest against the preserved scene depth (a glow eye behind a tree doesn't shine through), and the capture is cheap because only emissive meshes rasterize. `HalfFloatType` gives HDR headroom (emissives >1.0 linear contribute proportionally) and kills 8-bit banding in soft falloffs. From the capture, a **13-tap filtered downsample** walks a pyramid of `BLOOM_MAX_MIPS = 5` half-by-half RTs (1/2 … 1/32 physical res) — the **Karis average** (1/(1+luma) box weighting) on the first step prevents single-pixel fireflies from flickering at reduced res — then **3×3 tent-filter upsamples** walk back up, additively blending each mip into the next larger one (`AdditiveBlending` quads; `renderer.autoClear` must stay false through the up-walk). No step point-samples and no upsample magnifies more than 2×, which is why there's no pixelation despite the reduced-res blur. The bloom radius slider (`bloomRadius` in `userSettings`, 0–300%) maps to the per-step upsample weight `uScatter` (clamped 0.2–1.0): deeper mips contribute scatter^n, so higher values read as a wider, softer halo. The composite pass additively blends `bloomMips[0]` (half res — the final 2× is a bilinear fetch, invisible on content this blurred) with strength `BLOOM_COMPOSITE_STRENGTH`; when bloom is off the composite is `enabled = false` and `renderBloomChain` is skipped entirely. `onResize` rebuilds the mip RTs from physical pixels (multiply by `renderer.getPixelRatio()` yourself — the composer's logical size doesn't apply to the hand-rolled chain).
  - Tilt-shift is a **hybrid screen-Y band + depth-from-focus** blur. Blur radius is `max(bandMask, depthMask) * uBlurAmount`. `uFocus` (screen-Y of sharp band) and `uFocusZ` (view-space distance to the orbit target) are both updated each frame in `main.js`. The 9-tap rotational disc blur sums weights to exactly 1.0 and accumulates in **gamma-2.0 perceptual space** (`sqrt` encode each tap, square-decode the result) — linear-HDR blur lifts dark-on-light edges and reads as wash-out; gamma-space blur preserves perceived saturation.
  - The combined depth-FX pass runs three depth-driven effects in one fullscreen quad: sobel-on-linear-depth outlines (skipped on the sky/far-plane), 6-tap hex-ring contact AO, and painterly far-field fog (smoothstep mix toward the biome's fog color set by `world.js` on every regen). Each effect has its own `uXStrength` uniform that drops to 0 when its FX-panel checkbox is off; the pass auto-disables when all three are 0.
  - The custom sRGB output pass only does the linear → sRGB gamma encode (the renderer's tone mapping runs implicitly on the final canvas blit). Using three's standard `OutputPass` would apply ACES a second time and crush very dark biomes (obsidian, ashen) to pure black.
  - Returns a stub under `LOWFX` (no composer, no depth pre-pass, `state.depthTexture = null`). Skipped entirely in inspect mode — `main.js` calls `renderer.render(scene, camera)` directly there because the composer's neutral-gray studio backdrop would tonemap to black.

Vertex shader displaces along normal; fragment shader uses a 3D point hash on object-space cells to discard non-hair pixels. `sharedFurUniforms.uLightDir` is updated once per frame in `main.js`. ### The determinism trick (important when touching world-gen)

`generateWorld` is `async` and installs a seeded PRNG (`mulberry32(seed)`) over `Math.random` for the duration of world construction, but it does **not** hold the install across `await`. The PRNG is saved and restored around every async yield so the loading UI can paint between phases without unrelated animation frames consuming seeded random values. The mechanism (in `src/world.js`):

- `originalRandom = Math.random` is captured once; `seededRandom = mulberry32(seed)` is built once.
- `installSeededRandom()` sets `Math.random = seededRandom`; `restoreRandom()` puts the original back.
- `yieldIfNeeded(force)` — the wrapper every world-gen phase awaits — calls `restoreRandom()`, awaits `nextGenerationFrame()` (letting the loading screen paint and other microtasks run against the real `Math.random`), then calls `installSeededRandom()` on resume so the seeded stream picks back up exactly where it left off.

So every `Math.random()` call inside a builder reproduces from the seed, and per-frame `stepX` updaters (which run after the final restore) keep natural variation. **If you add new async work inside the deterministic window, it must go through `yieldIfNeeded()` — do not write a bare `await` and then re-`install` the PRNG yourself, and do not call `Math.random = mulberry32(seed)` after an `await` (that would reset the stream and burn the determinism of every downstream roll).** Sync code between two `yieldIfNeeded` calls is already inside the seeded window — no wrapping needed. Per-frame animation, timers, and user-interaction handlers all run after the final restore and use the real `Math.random`.

### Seed → biome → layout coupling

The biome is picked by the first `Math.random()` call inside `generateWorld`, and `pickLayout()` runs immediately after — both stay inside the deterministic window so the seed alone identifies the entire world. `newRandomSeed(opts = {})` accepts `{ excludeBiomeId, allowedBiomeIds }` (the Field Guide biome filter passes `allowedBiomeIds`; a bare biome-id string is still accepted for back-compat). It rerolls up to 64 times to satisfy both the filter and the no-repeat rule, then falls back to a 32-attempt pass that keeps the filter but drops the no-repeat rule (up to 96 rolls total), and finally gives up with an unconstrained random seed.

### Layout system

`pickLayout()` returns `{ centers, planeSize, boundRadius, kind }` describing one island (round / oblong / kidney). It's always single-island today — archipelagos were tried but the creature roaming and silhouette didn't read well across disconnected chunks (see comment in `terrain.js`). The infrastructure is still multi-center though: `centers` is an array, `islandFalloff` is per-center, and `pickGroundPoint(maxRadiusFrac)` / `nearestCenter(x,z)` already weight by island area. **Anything that needs to place objects on solid ground must go through `pickGroundPoint`** rather than raw `Math.random()` over XZ, so re-enabling archipelagos later doesn't require rewriting every placement call.

### Density scaling

Biome `floraCount` and `creatureCount` values in `biomes.js` were tuned against a 76-unit base. The actual `ISLAND_SIZE_BASE` may be larger (currently 100); `src/state.js` exports a separate `DENSITY_BASE = 76` anchor, and `world.js` scales the per-world target counts by `state.ISLAND_SIZE / DENSITY_BASE` so larger or shape-stretched layouts stay cute-dense instead of going sparse. If you retune biome counts, update them at the `DENSITY_BASE` reference, not at the current base size.

### Wind sway

`applyWindSway(material, strength)` patches a `MeshStandardMaterial`'s vertex shader via `onBeforeCompile` so geometry bends more the higher its local Y (trunks at y≈0 stay put, leaves and grass tips sway). All instances share one `windUniforms.uTime` uniform advanced each frame. Apply it to any new flora that should bend in the wind; it works on both regular meshes and `InstancedMesh` (the shader checks `USE_INSTANCING`).

The grass field in `grass.js` has its own self-contained wind shader (not via `applyWindSway`) with per-blade noise gusts and a swirling bend direction; its `uWindStrength` and `uWindScale` are live-multiplied by the settings panel via `state._reapplyWindSettings`. Disabling wind from the settings panel **freezes `state.windUniforms.uTime` advancement in `main.js`** (so applyWindSway-driven foliage settles to a still pose) AND zeros the grass `uWindStrength` (so its noise-based bend goes flat). The combination is what makes "wind off" actually look still.

### Grass push system

The grass shader runs a small **creature → blade bend** pass each frame, after wind and before the distance fade. Up to `MAX_PUSHERS` (currently 40, in both the JS const and the GLSL `#define`) circular pushers are written from `stepGrass` and consumed in the vertex stage:

- Each pusher is a `vec4 (worldX, worldZ, radius, strength)`. The shader tests each blade vertex against every active pusher (early-out on `radius < 0.001`), applies a `(1 − d/r)²` falloff, weights by `aTipFactor²` so roots stay anchored, and adds a radial bend outward from the pusher center plus a small Y dip so trampled grass reads as flattened rather than just splayed.
- `stepGrass` populates the array from `state.creatures` (skipping airborne fliers via `c.flies && c.landState !== "landed"`) and every segment of every caterpillar. Creature positions are mesh-local (under `state.world`); `stepGrass` multiplies by `worldScale` so the comparison happens in the shader's world-XZ frame.
- **Slot sizing matters.** Smaller than the entity count and creatures past the cap appear to "toggle" bending on and off as fliers take off / land and free up slots. 40 covers the worst-case biome (~18 walkers + ~5 caterpillars × up to 4 segments).
- **Bend direction is computed in world space, but applied to mesh-local `transformed.x/.z`.** Each blade instance has a random Y yaw in its `instanceMatrix`, so a world-space push has to be inverse-rotated through the instance's XZ basis before it can be added to `transformed`. The shader does this with `dot(axW, pushWorld) * invXZScaleSq` (and the same `axW`/`azW` for wind). Without this, every blade applies the bend along its own rotated local-X and the field reads as random instead of coherent. Any new world-space displacement on the grass needs the same treatment.

### Live grass density

The density slider operates on `mesh.count` of the existing `InstancedMesh` — no rebuild, no regen. `makeGrassField` over-allocates slots up to `MAX_DENSITY_MULTIPLIER × biome stock` and stores both bounds on `state.grass` as `stockCount` (slider = 100%) and `maxPlaced` (slider = max). `applyGrassSettings` in `ui.js` computes `mesh.count = clamp(0, maxPlaced, round(stockCount × grassDensity))` and updates the `uHeightMul` uniform. Per-instance attributes (`aWindSeed`, `instanceColor`) are sized to `maxPlaced` so increasing density at runtime still has valid data behind the new visible blades. The grass-enabled toggle just forces `mesh.count = 0` while leaving `grassDensity` untouched, so re-enabling restores the previous look exactly.

### Day/night cycle

`updateDayNight(t)` lerps the scene's sky/fog/sun/hemi colors between the current biome's palette (snapshotted into `dayNight` at world build) and a generic `NIGHT_*` palette, and arcs the sun across the sky. Driven by either `userSettings.autoCycle` (a 120s cycle) or `userSettings.manualDayFactor` (settings-panel slider). Fog density is also scaled by `userSettings.fogMultiplier`.

### Biome-flag pattern

Several per-biome behaviors are gated by optional flags rather than hardcoded biome ids. When adding a new per-biome behavior, prefer a flag over `if (biome.id === ...)`:

- `water` (color) — adds a translucent water plane.
- `cloudlike` — `makeIslandUnderside` perturbs more vertices for a puffball silhouette, and `makeCloudSwirl` (`sky.js`) adds a torus halo of shader-driven swirling clouds around the island. The swirl shader runs two-octave value noise scrolled in opposing directions plus a low-frequency UV warp; alpha tapers to 0 at the torus poles so the band has soft top/bottom edges. Time uniform is shared with `state.windUniforms.uTime`, so no dedicated per-frame step is needed.
- `glowFlowers` — wildflower instances get an emissive material.
- `glowEyes` — creature pupils render emissive in the accent color.
- `furProbability` (0..1) — per-creature fur roll. Each walker (non-flier, non-fish) and each non-snail caterpillar independently rolls `Math.random() < furProbability` at build time, so the same biome can mix fuzzy and smooth creatures. Defaults to 0 when unset.
- `creatureKind: "fish"` — `makeCreature` builds a non-landing flier with fin-like ears and a tail fin instead of wings; gentle fin sway in `stepCreature`.
- `hasWillowisps` — the biome spawns will-o'-wisps (`state.willowisps`, stepped in their own `animate()` phase).
- `giantFlora: { kind, scaleMul, maxRadiusFrac, effect }` — promotes one placed instance of `kind` to a scaled-up "giant" specimen (`world.js`'s giant-flora promotion pass); `effect` (`"muteWind"` or `"willowisp"`) gates an additional per-effect hookup on that instance.
- `guaranteeBurrower` — regen always places at least one burrower-type creature on this biome instead of leaving it to the normal creature roll.
- `treeFloraRadiusFrac` — overrides the placement radius fraction used for `tree`/`leafballtree` flora kinds on this biome.

### Sim pause

The animation loop in `main.js` derives a single `paused` boolean from `isPhotoMode() || isSelectingCreature() || isManualPaused()`. When `paused`, the loop holds `dt` at 0 and freezes the simulation time `t` at `state.lastSimT` — every `stepX` uses `sin(t * speed)`-style idle bobbing, so unfreezing `dt` alone is not enough (animations would still drift). Camera input and rendering keep running on the frozen state. Selection mode is paused so users can click on an otherwise-moving target; spacebar toggles `_manualPause` (suppressed while stroll/photo/selection are already paused, to keep their own exit semantics clean). The `#pause-banner` element shows "paused · press space to resume" while manual pause is on.

### Follow anchor (caterpillar gotcha)

Regular creatures store their position on `c.group.position` — the group transform is what moves. **Caterpillars and snails are the exception**: their group stays at the origin and the head + body segment *meshes* inside it are what get repositioned (so the trail-following code can work in world space). `main.js`'s follow camera therefore reads `(ft.segments ? ft.segments[0] : ft.group).position` — if you add a new follow-tracked entity that uses the caterpillar pattern (segments instead of a moving group), give it a `segments` array so the camera finds the head.

The caterpillar head mirrors the walker terrain-tilt pattern (`stepCreature`'s slope sampling): four `heightFn` samples around the head along heading × perpendicular, then eased pitch/roll into `head.rotation.x`/`.z`. `makeCaterpillar` sets `head.rotation.order = "YXZ"` once at construction so the pitch/roll resolve in the body frame after yaw — without that, a heading-changed caterpillar would roll around world-X. The idle nodding bob is folded into the pitch target so it stacks on top of the slope rather than overwriting it.

Yaw is slewed, not snapped. `c.heading` is the actual direction (used for movement, slope sampling, and visual yaw); `c.headingTarget` is the aim. Random thinks and edge avoidance write `headingTarget`; each frame `c.heading` rotates toward it at `c.turnRate` rad/s (caterpillar 3.0, snail 2.0) via shortest-angle diff. Obstacle slides snap both `heading` and `headingTarget` to `slide.heading` because the slide's `nx, nz` is already deflected and the values must match this frame. Any new logic that re-aims a caterpillar should set `headingTarget`, not `heading`, unless it also commits to a same-frame position change.

### Flier landing system

`makeCreature(flies=true)` creatures have a four-state landing FSM in `stepCreature`: `flying ↔ descending ↔ landed ↔ ascending`. The `landTimer` plus `c.currentHover` (lerping between `hoverCeil = hoverHeight*(1-0.7*sleepiness)` and `restH = 0.35*scale`) drive transitions. Three cross-cutting safeguards:

- **Water:** while `state.waterMesh && heightFn(pos.x, pos.z) < WATER_AVOID_Y`, the FSM is forced to `flying` (and `perchTarget` cleared). Sleepy-driven descents are also blocked over water so a drowsy flier won't ditch mid-lake.
- **Obstacles:** `avoidObstacles` accepts an optional `y` argument. Walkers pass `undefined` (full collision); fliers pass `pos.y` and obstacles with `top + 0.15 < y` are skipped — so a flier above the canopy can pass straight over a tree. It also accepts `skipX, skipZ` to ignore one specific obstacle (the perch's own mushroom).
- **Mushroom perches:** on `flying → descending`, `pickPerchForFlier(c)` gates on a 55% roll (the other 45% descend to the ground normally). It early-outs for fish and bumblebees, then scans `state.perchSpots`. Perches whose occupant is a different creature that still has a live parent in the scene (`occupant.group?.parent`) are skipped, so kids don't evict each other. **`flyer_nest` perches are searched globally** (no distance cap) and preferred — the nearest nest wins over the nearest non-nest cap regardless of distance. Other perch kinds (mushroom caps etc.) are only considered within 6 units (squared distance `< 36`). The flier claims whichever wins (`nearestNest ?? nearestOther`). Once claimed, the flier's heading is steered toward the perch (jitter from the random think is skipped while homing), speed is scaled down close in, `targetH` holds an approach altitude until xz < 1 unit, and the final `landed` commit requires xz² < 0.16. The `pos.y` floor is a smoothstep blend between `ground` and `perchTarget.y + perchLift` over a 0.5–4 unit XZ window, with `c.perchFloorWeight` low-pass filtering the blend factor so the rate of change is capped (jump-free approach AND takeoff). `perchTarget` persists through ascent and is cleared lazily once the floor weight has decayed back to ~0. The `perchLift` is **negative** (`-0.04 * c.scale`) — the body's half-Y is slightly larger than `restH`, so a small downward bias keeps the contact convincing instead of floating above the cap.

Mushroom builders attach `g.userData.capTopY` to expose the actual local cap-top Y; `world.js` uses `f.position.y + capTopY * scale` for the perch world-Y rather than the looser per-kind `OBSTACLE_TOP` table (which only needs to be approximate for the air-passing filter).

### HUD

`index.html` defines the static HUD shell. `finalizeWorldHud` (`src/world-hud.js`, called at the end of `generateWorld`) writes biome name, creature/flora/bird counts, and seed into `#biome-name`, `#ground-creature-count`, etc. Styling is purely in `style.css` (film grain, vignette, corner marks, fonts from Google Fonts).

### Field Guide catalog

The Field Guide (`G` key, or the settings-panel button) is a per-biome checklist of fauna/flora subjects that unlocks as the user photographs them in photo mode. `src/catalog.js` and `src/photoSubject.js` implement the subsystem; `ui.js` wires it to the panel and the photo-mode reticle.

- A **subject** is `{ key, category, variant, biomeId, label }`, built by `buildCatalogKey` / `buildCatalogSubject` (`category: "creature"` normalizes to `"fauna"` for storage keys). `getBiomeCatalogEntries(biome)` enumerates every subject a biome can offer; `filterCatalogEntriesForWorld` narrows that list to what the *current* seed/world actually has, so the panel never offers a subject the loaded world lacks.
- **Persistence is split across two stores.** Entry metadata (seed, timestamp, label) lives in `localStorage` under `smallworld:catalog:v1`. The photo blobs themselves live in an IndexedDB database (`smallworld-catalog`, `photos` object store) keyed by the catalog key, so large binary thumbnails don't bloat `localStorage`. `makeCatalogStore(...)` wraps both stores behind one API.
- **Reticle capture flow:** in photo mode, `findPhotoCatalogSubject({ camera, root })` (`photoSubject.js`) raycasts from screen center, walks the hit object's ancestor chain looking for `userData.catalog` (or reconstructs a subject from `{category, variant, biomeId}` via `buildCatalogSubject`), and returns the nearest hit's subject. The shutter click uses this to know what was framed; the review screen then offers to save it, and if an entry already exists for that key, asks whether to keep or replace the saved shot.

## Vibe

This project is **cute**. That's a design constraint, not a vague aspiration — when adding or tweaking anything visible, keep it consistent with the existing feel:

- **Big eyes, small bodies.** Creatures have oversized white-sclera eyes with dark pupils set forward on the face. Don't shrink them, don't add realistic proportions, don't go menacing.
- **Rounded, blobby silhouettes.** Bodies are jittered icospheres, not boxes or sharp polys. Flora is chunky and stylized (cone-tiered pines, capsule cacti, hemisphere mushroom caps) — never photorealistic.
- **Smooth, easeful motion.** Movement is gentle drifts, bobs, and arcs — never linear, never twitchy. Look at `stepCreature` / `stepButterfly` for the reference cadence: soft acceleration, slight overshoot, idle breathing.
- **Cartoony, not gritty.** Even the "ashen wastes" and "crimson dunes" biomes are stylized and warm, not bleak. `skull` is the darkest motif and it's still rounded.
- **Saturated but soft palettes.** Biome colors lean painterly. Tone mapping is ACES Filmic with mild exposure; fog is heavy. Don't introduce harsh contrast or neon.

If a change would make something look scary, sharp, realistic, or twitchy, it's wrong for this project even if it's technically nicer.

## Conventions worth keeping

- **Runtime deps via npm.** three.js and simplex-noise are installed locally (`package.json`) and bundled/tree-shaken by Vite at build time. No CDN importmap needed. The `vite.config.js` configures minification, content hashing, and the dev server.
- **Adding a biome:** append to `BIOMES`. If a new flora kind is needed, add it to `FLORA_BUILDERS` first; the biome's `flora` array references it by string. Also extend the per-biome `WILDFLOWER_PALETTES` / `GRASS_DENSITY` / `FLOWER_DENSITY` / `PEBBLE_DENSITY` tables (they fall back to defaults via `??` but tuned values look better).
- **Adding a creature type:** follow the existing `makeX` + `stepX` split and push to the corresponding array inside `generateWorld`, then call its `stepX` from `animate()`.
- **Cross-cutting per-biome behavior:** add a flag on the biome (see "Biome-flag pattern" above) and check it in the relevant builder, rather than branching on `biome.id`.
- **Placement:** use `pickGroundPoint()` rather than raw XZ randomness so multi-island layouts work.
- **Disposal:** `disposeGroup` walks geometries/materials when the world is rebuilt. New mesh-allocating code that lives on the `world` group is covered automatically; new top-level scene additions are not.
- **Devtools handle:** `main.js` exposes `window.__sw = { state, controls, scene, camera, renderer }` for inspection from browser devtools. It's never read by the app itself — safe to leave, safe to remove. Useful for reading live uniform values, manipulating `state.grass.uniforms.uPushers`, or programmatically setting up tricky camera angles.
